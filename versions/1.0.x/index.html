    bxSites Cloud

    Everything works on any host. Cloud adds the rest.

    Publish with one command, then add the parts a static site can't do on its own: forms, comments, managed content and a live MCP server for AI agents.

    bxsites.yaml
    cloud:
  siteId: "your-site-uuid"
  apiUrl: "https://cloud.bxsites.app"
  comments: true
    terminal
    $ export BXSITES_CLOUD_TOKEN=cb_...
$ bxSites publish

    • Hosting with publish

      Ship site/ to your Cloud site over its publish API.

    • Contact forms

      Drop in a contact-form block. Spam filtering and notifications are set up in Cloud.

    • Comments

      A comments block puts a thread on any page.

    • Managed content

      Edit blocks in the Cloud portal and bake them into your pages at build time.

    • A public MCP server

      Set mcp: true and Cloud serves your published site to AI agents, read-only.

    Forms, comments, managed content and the MCP server depend on your Cloud plan. Deploying anywhere else stays fully supported.

    Everything included

    One tool, the whole pipeline.

    From folder structure to a deployed URL — theming, search, i18n, blog, and shipping are already wired in.

    Markdown in, static HTML out

    Point it at a docs|src/ folder and it renders a complete site into site/, no server required to host it.

    Folder structure is nav structure

    Nest folders and files under docs/ and the navigation builds itself, in the order you set via frontmatter.

    Ten built-in themes

    A full gallery — bootstrap, material, tailwind, and seven more — all overridable with your own theme.

    Static, client-side search

    A MiniSearch-powered search box plus a Cmd/Ctrl+K command palette, wired against a search index built at build time.

    A blog, out of the box

    Drop posts under docs/blog/posts/ and get authors, categories, year archives, RSS feeds, and featured images — zero config.

    Fast, air-gapped by default

    Bootstrap, highlight.js, Alpine.js, MiniSearch and (opt-in) Mermaid all vendored — a built site needs zero outbound requests.

    A real plugin system

    A plugin is just another installed BoxLang module — no separate plugin API to learn.

    Ship it anywhere

    bxSites deploy ships to S3, Azure, GCS, Firebase, FTP/SFTP, rsync, Cloudflare Pages, or GitHub Pages.

    Versions & i18n

    Multiple doc versions and translated trees, both nav-aware out of the box.

    Reusable variables & magic functions

    {{ dotted.path }} pulls from bxsites.yaml's own variables block — no plugin, no wiring.

    Rich content blocks

    Tables, buttons, prompts, expandables, tabs, and embedded OpenAPI specs — a GitBook-style block library on top of plain Markdown.

    Import an existing theme

    theme:import --source=mkdocs|jekyll|hugo converts another generator's own templates into a bx-sites scaffold.

    Already in your build

    Docs as a build step, not another toolchain.

    Java or BoxLang shops don't need a Node pipeline bolted on. Generate docs from the build you already run — Gradle, Maven, or a Spring Boot app.

    Works with
    Scan controllers
    OpenAPI
    Javadoc / DocBox
    bxSitesBuild

    Gradle plugin

    Run ./gradlew bxSitesBuild alongside your normal build — docs regenerate on every CI run.

    Maven plugin

    Bind bxsites-maven-plugin to the package phase — mvn install ships docs with the artifact.

    Spring Boot / ColdBox

    Point bxSites at a Spring Boot or ColdBox app and it scans your REST endpoints and OpenAPI spec into browsable reference docs.

    Javadoc & DocBox, ingested

    Point bxSites at your Javadoc or a ColdBox app via DocBox — reference pages generate themselves.

    $./gradlew bxSitesBuild|mvn bxsites:build
